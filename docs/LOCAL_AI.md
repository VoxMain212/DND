# Локальная генерация персонажей, PNG и ведущий — версия 0.5

Подключение к моделям реализовано, но сами Ollama, ComfyUI и веса на этом ноутбуке ещё не установлены. Проверены очередь, протоколы API, обработка картинок и передача по сети. Качество и скорость настоящей нейросетевой генерации пока не измерены.

## Что можно проверить прямо сейчас

1. Запустите проект через F5 и создайте комнату.
2. Откройте **«Мастерская»** в верхней панели.
3. Оставьте **«Тест без ИИ»**, введите описание и нажмите **«Создать персонажа и PNG-фишку»**.
4. Игра перекрасит готовый рисунок, сохранит запрос в биографии и применит PNG к вашему персонажу. У остальных игроков картинка появится автоматически.

Этот режим не понимает внешность из текста и не является нейросетью. Он нужен для проверки готового пути «запрос → очередь → PNG → кэш → сеть → фишка». При выборе **«Локальный ИИ»** ошибка сервера не подменяется тестовой картинкой.

## Что делает режим «Локальный ИИ»

1. На ПК хоста проверяется ComfyUI и наличие выбранной модели SD 1.5. Очередь ComfyUI должна быть свободна.
2. Ollama создаёт имя, биографию на русском и описание внешности на английском по JSON-схеме. Стиль: чёрный юмор, абсурд и сухая ирония.
3. Игра проверяет структуру и длину полей. Незапрошенные поля удаляются; модель не может изменить HP, урон или броски.
4. ComfyUI рисует нового персонажа в полный рост на белом фоне, 512×512, один экземпляр.
5. Игра в фоновом потоке удаляет связанный с краями белый фон и вписывает персонажа в прозрачную PNG 256×384.
6. PNG сохраняется у хоста и передаётся клиентам. Им не нужны ни модели, ни Python, ни ComfyUI.

Завязка приключения использует только текстовую модель и пока относится к существующей таверне и одному бою со скелетом. Ведущий во время боя включается отдельно на вкладке «Партия». Карты, картинки врагов и переходы между сюжетными сценами пока не генерируются.

## Ведущий во время партии

В **«Мастерская → Партия»** выберите **«Локальный ИИ — Ollama»**. Используется текстовая модель из вкладки «Модели хоста»; ComfyUI для ходов не нужен. Обычные кнопки движения и атаки работают без запроса к модели.

Текст игрока и небольшой снимок стола передаются в `/api/chat` с JSON-схемой намерения: move, attack, speak, end_turn или clarify. Модель не получает права менять HP и создавать предметы. Движок повторно проверяет соседство, препятствия, цель, очередь и ресурсы. После успешного расчёта второй запрос получает факты из журнала и создаёт короткое описание. Юмор задаётся системной инструкцией. Смена целей и сцен пока не реализована.

Ведущий использует CPU, до четырёх потоков, контекст 4096, до 500 выходных токенов на запрос, `keep_alive=0`; таймаут каждого этапа 120 секунд. Пока запрос выполняется, стол блокирует команды. Отменить его может хост или автор действия через вкладку «Партия». Отмена HTTP-запроса не гарантирует немедленную остановку вычислений внутри Ollama; новые ответы старого запроса игра игнорирует. Уже рассчитанное действие сохраняется при отмене описания. Ошибочный JSON или недоступная модель не заменяются скрыто тестовым режимом.

Без установки модели выберите **«Тест без ИИ»** и введите «иду вниз», «иду вправо», «атакую», «говорю …» или «завершаю ход». Это простой распознаватель, а не нейросеть. Новые способности и неоднозначные действия он не выполняет.

## Ollama: текстовая модель

Установите Ollama по [официальной инструкции для Linux](https://docs.ollama.com/linux) или [странице загрузки для своей ОС](https://ollama.com/download).

Запустите локальный сервис, если он ещё не запущен:

```sh
ollama serve
```

В другом терминале скачайте выбранную модель:

```sh
ollama pull qwen3:4b-instruct-2507-q4_K_M
```

Это квантованный кандидат на 4B; [страница модели](https://ollama.com/library/qwen3:4b-instruct-2507-q4_K_M) указывает размер около 2,5 ГБ. Команда скачивания нужна только хосту. Игра обращается к `http://127.0.0.1:11434/api/chat`.

В **«Мастерская → Модели хоста»** должно быть такое же имя текстовой модели. Настройка не скачивает модель автоматически.

## ComfyUI: новая картинка

Установите ComfyUI в отдельное Python-окружение по [официальной инструкции](https://docs.comfy.org/installation/manual_install). На Linux для работы RTX нужна совместимая установка драйвера NVIDIA и PyTorch; команды установки зависимостей следует брать из инструкции под используемую систему. Не устанавливайте тяжёлые зависимости в системный Python проекта игры.

Для начального эксперимента используется checkpoint Stable Diffusion 1.5. Файл [v1-5-pruned-emaonly.safetensors](https://huggingface.co/stable-diffusion-v1-5/stable-diffusion-v1-5/blob/main/v1-5-pruned-emaonly.safetensors) в репозитории модели занимает около 4,27 ГБ. Скачайте именно отдельный файл, а не весь репозиторий моделей, и положите его в `ComfyUI/models/checkpoints/`. Другой совместимый checkpoint SD 1.5 можно выбрать по точному имени файла в мастерской.

Из папки ComfyUI, в активированном окружении, начальный вариант запуска для испытаний на 4 ГБ VRAM:

```sh
python main.py --listen 127.0.0.1 --port 8188 --lowvram --cpu-vae --disable-auto-launch
```

Эти параметры поддерживает [CLI ComfyUI](https://github.com/Comfy-Org/ComfyUI/blob/master/comfy/cli_args.py). Они являются начальной конфигурацией для замеров, а не гарантией достаточной памяти или быстрой генерации на ноутбуке. Пользовательский workflow собирать не нужно: игра отправляет граф из стандартных узлов ComfyUI.

В **«Мастерская → Модели хоста»** укажите `v1-5-pruned-emaonly.safetensors` или имя реально установленного SD 1.5 checkpoint. После этого выберите **«Локальный ИИ»** и создайте персонажа в лобби.

Не запускайте в этом экземпляре ComfyUI сторонние задания одновременно с игрой: игра проверяет очередь и вызывает `/free`, чтобы выгружать модели между этапами. Произвольные workflow и custom nodes не требуются.

## Память и очередь

- На хосте работает одна очередь генерации. У игрока может быть один ожидающий запрос; начало боя блокируется до её завершения.
- Текстовая модель запрашивается на CPU: `num_gpu=0`, до четырёх потоков, контекст 4096 и до 700 выходных токенов.
- `keep_alive=0` просит Ollama выгрузить модель после ответа. Это описано в [API Ollama](https://docs.ollama.com/api/chat).
- Для картинки: 512×512, batch 1, 16 шагов. Перед текстовым этапом и после завершения графического задания вызывается ComfyUI `/free`.
- Подготовка PNG выполняется в отдельном потоке. HTTP-запросы и ожидание очереди не блокируют игровой интерфейс.
- Ожидание текста ограничено 150 секундами, картинки — примерно четырьмя минутами плюс отдельный HTTP-запрос. При ошибке старый персонаж сохраняется.

Закрытие окна мастерской скрывает интерфейс, но не отменяет запрос. Выход из комнаты исключает применение запоздалого результата к другой комнате. Уже отправленная внешняя задача ComfyUI при этом может продолжить выполняться; после истечения времени ожидания сначала дождитесь её завершения в ComfyUI.

## Прозрачный фон и качество

Используется удаление однотонного белого фона от краёв картинки, а не нейросетевое выделение персонажа. Белые детали внутри замкнутого силуэта сохраняются. Сложный фон, дым, волосы и светлая одежда могут вырезаться плохо; если белого фона недостаточно, результат отклоняется и предлагается повторить генерацию.

SD 1.5 — базовый кандидат для проверки небольшого оборудования. Художественный стиль, качество анатомии, LoRA, более качественная маска и собственное обучение — следующие этапы. Наличие API-интеграции само по себе не подтверждает качество рисунка или подходящую скорость.

## Кэш и сеть

Сгенерированные PNG сохраняются в `user://portraits/<sha256>.png`. На обычном Linux каталог данных Godot для проекта находится в пользовательской папке `app_userdata`; точное расположение зависит от ОС и способа запуска. Для восстановления партии с одним игроком используйте отдельные сохранения на вкладке «Партия»: они содержат профиль и PNG внутри файла. Восстановление сетевой группы пока не поддерживается.

Изображения передаются надёжным отдельным каналом ENet по 16 КиБ за кадр; небольшие команды ходов используют другой канал. Получатель проверяет итоговый SHA-256, сигнатуру PNG, размер файла до 512 КиБ и размер изображения до 768×768 перед декодированием. Готовые изображения нормализуются до 256×384. В памяти ограничено 64 сгенерированных портрета за запуск.

Поздно подключившийся игрок получает недостающие PNG из кэша хоста. Картинка с уже известным хешем используется повторно. Изменённые вручную встроенные PNG из `assets/tokens` по-прежнему нужно обновлять у всех участников: этот механизм передаёт именно сгенерированные портреты.

## Проверка реализации

`tests/test_generation.gd` проверяет валидацию, обработку PNG, неизменность характеристик, очередь и защиту от запоздалого результата. Для Ollama и ComfyUI используются локальные HTTP-фикстуры `tests/mock_ai_server.py`, которые не являются нейросетями.

`tests/generation_peer.gd` проверяет настоящую передачу PNG между двумя процессами Godot с раздельными каталогами кэша. Тест не может пройти за счёт того, что два процесса случайно читают один файл с общего диска.

`tests/test_director_saves.gd` проверяет команды ведущего через HTTP-фикстуру, отказ от недопустимых намерений, отмену, сохранение рассчитанного действия при сбое описания и восстановление партии из ограниченного JSON с проверкой PNG. В сетевом тесте клиент выполняет текстовый ход через хоста.

Проверена также генерация тестового эскиза из упакованного PCK. Работа настоящих весов, расход памяти, скорость генерации и Windows-сборка пока не проверены.
